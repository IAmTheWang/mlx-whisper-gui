# web/src/views

One file per UI pane, each a `render<Name>(container, ...args)` function. Composed together in `main.ts`.

- `browser.ts` — `renderBrowser`: server-side directory browser + video multi-select (checkboxes, disabled for non-video files per `entry.isVideo` from the backend). Persists the last-visited path in `localStorage` (`whisper-gui:lastPath`) so it reopens where the user left off. Also exposes `getEntry(path)`, backed by a `knownEntries` map accumulated across every directory visited this session (not just the currently displayed one) — lets `main.ts` look up `hasSrt` for a file selected in a directory the user has since navigated away from. Sort order (Name/Date/Type, click to toggle asc/desc) is rendered via `../sortControls.ts`'s `renderSortRow()` and persisted in `localStorage` (`whisper-gui:browserSort`) — purely a client-side re-sort of the already-fetched entries, the backend's own default order (folders first, name ascending) is untouched.
- `jobForm.ts` — `renderJobForm`: engine/model/language `<select>`s plus the "Start Transcription" button. Purely presentational — `onEngineChange(engine)` and `onStart(engine, model, language)` hand control back to `main.ts`, which fetches the engine-specific model list and does the actual `createJob` calls per selected file. Defaults the model `<select>` to `mlx-community/whisper-large-v3-mlx` (falls back to whatever the browser renders first if that ID isn't in the list) and the language `<select>` to `ja`, instead of leaving both on the DOM's default first `<option>`. The model `<select>` itself is rebuilt wholesale via the controller's `setModels()` whenever the engine changes (or Settings saves a new whisper.cpp model directory) — an empty list renders a disabled placeholder option and disables Start alongside the existing zero-files-selected check.
- `settings.ts` — `openSettingsModal(onSaved?)`: a modal overlay (same pattern as `folderPicker.ts`) for the `mlx_whisper`/`ffmpeg`/`whisper-cli` path overrides (each with its live `resolvedVia` badge), the whisper.cpp model directory (with a Browse… button reusing `openFolderPicker`), the optional whisper.cpp VAD model path (plain text input, no Browse button — it's a single file the user downloads separately, not a directory `openFolderPicker` can select), and the default-engine preference. Wires up the `getSettings`/`saveSettings` API functions that existed but had no UI consumer before this view was added. On save, the whole panel is rebuilt from the server's fresh response (`renderLoaded(settings, savedMessage?)`) rather than patched in place — the success/error message is passed as a parameter into that rebuild instead of being written onto the old (about-to-be-detached) note element, which would otherwise silently never render.
- `jobList.ts` — `renderJobList`: polls-on-demand (`refresh()`) list of all jobs, newest first (matches the backend's `ListJobs` ordering). Click a row → `onSelect(id)`.
- `jobDetail.ts` — `renderJobDetail`: the single most stateful view. Loads the job once via `getJob`, then opens an SSE stream (`openJobStream`) for live `log`/`progress`/`state` updates. Handles the sidecar-copy note (saved next to video vs. copy failed — see `jobmanager.copySrtNextToVideo`), the "Save to Video Folder"/"Save to Folder…" buttons (`moveSrt` in `../api.ts`, folder picker from `folderPicker.ts`), and the cancel button (hidden once the job reaches a terminal state). Always call `.destroy()` on the previous instance before rendering a new job's detail (see `main.ts`'s `openJobDetail`) — it closes the SSE connection.
- `folderPicker.ts` — `openFolderPicker(onSelect)`: a directory-only modal variant of `browser.ts`'s browser, used by `jobDetail.ts` to let the user pick an arbitrary destination folder for the `.srt`. Remembers the last folder browsed to in `localStorage` (`whisper-gui:lastSrtDestDir`), same pattern as `browser.ts`'s own last-visited path, so it reopens where the user left off. Has its own Name/Date sort row (no "Type", since it only ever lists directories) via `../sortControls.ts`, with its own `localStorage` key (`whisper-gui:folderPickerSort`) — independent of `browser.ts`'s sort state, this view has no shared rendering code with it.

## Conventions

- State labels (`queued`/`running`/`done`/`failed`/`cancelled` → display text) are duplicated as `STATE_LABEL` in both `jobList.ts` and `jobDetail.ts` rather than shared — keep both in sync if the state set ever changes.
- These views talk to the backend only through `../api.ts` and `../sse.ts` — no direct `fetch`/`EventSource` calls here.
